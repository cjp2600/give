# Native terminal integration

Investigated 2026-10-18 against upstream source and published crate documentation.

## Recommendation

Use `alacritty_terminal = 0.25.1` and `portable-pty = 0.9.0` behind an application-owned GPUI view. This is an integration recommendation, not a claim that a completed terminal exists in this repository. Alacritty 0.25.1 declares Rust 1.85 and Apache-2.0; the current published Alacritty terminal release is 0.26.0, while portable-pty remains 0.9.0. Pinning 0.25.1 matches the GPUI example investigated. Sources: [published Alacritty manifest](https://docs.rs/crate/alacritty_terminal/0.25.1/source/Cargo.toml), [current Alacritty docs](https://docs.rs/alacritty_terminal/latest/alacritty_terminal/), [portable-pty docs](https://docs.rs/portable-pty/0.9.0/portable_pty/).

`gpui-terminal` 0.1.0 matches our exact GPUI 0.2.2 dependency and uses Alacritty 0.25.1 plus portable-pty 0.9. Its MIT OR Apache-2.0 code is a useful rendering reference, but its mouse-selection and scroll handlers are TODOs, it has no IME input-handler implementation, and its event bridge drops PTY replies. Depending on it unchanged would miss requirements. Sources: [manifest](https://docs.rs/crate/gpui-terminal/0.1.0/source/Cargo.toml.orig), [view source](https://raw.githubusercontent.com/zortax/gpui-terminal/main/src/view.rs), [event source](https://raw.githubusercontent.com/zortax/gpui-terminal/main/src/event.rs), [renderer source](https://raw.githubusercontent.com/zortax/gpui-terminal/main/src/render.rs).

Ghostty alternatives introduce another toolchain and GPUI revision: `gpui-libghostty` is alpha, requires Rust 1.95 and Zig 0.16, and pins git GPUI. `Xuanwo/gpui-ghostty` also pins git GPUI and Zig. Neither is a drop-in for our Rust 1.94 / crates.io GPUI setup. Ghostty's current native embedder header explicitly describes itself as internal and directs external users toward `libghostty-vt`. Sources: [gpui-libghostty](https://github.com/behzade/gpui-libghostty), [gpui-ghostty](https://github.com/Xuanwo/gpui-ghostty), [Ghostty header](https://github.com/ghostty-org/ghostty/blob/main/include/ghostty.h).

## Alacritty APIs

Create `Term::new(Config, &dimensions, event_listener)` with an application type implementing `grid::Dimensions`; use `vte::ansi::Processor::new()` and `processor.advance(&mut term, bytes)` for PTY output. `Config::scrolling_history` defaults to 10,000 lines. `Term::resize(dimensions)` handles grid reflow. Source: [published terminal implementation](https://docs.rs/crate/alacritty_terminal/0.25.1/source/src/term/mod.rs), [minimal state wrapper](https://raw.githubusercontent.com/zortax/gpui-terminal/main/src/terminal.rs).

`term.renderable_content()` returns `display_iter`, `selection`, `cursor`, `display_offset`, `colors`, and `mode`. Paint only this visible grid. Grid line coordinates include negative history positions; viewport row is `point.line.0 + display_offset as i32`. Respect wide-character spacer flags, combining characters, inverse/dim/bold/italic/underline, palette overrides, hidden/blinking cursor and cursor shape. Avoid holding the terminal mutex while shaping text. Source: [terminal implementation](https://docs.rs/crate/alacritty_terminal/0.25.1/source/src/term/mod.rs).

History navigation uses `term.scroll_display(Scroll::Delta(lines))`, `PageUp`, `PageDown`, `Top`, or `Bottom`. Text selection uses public `term.selection`, `Selection::new(SelectionType, Point, Side)`, `Selection::update`, and `term.selection_to_string()`. Map mouse coordinates back through the display offset. Sources: [grid implementation](https://docs.rs/crate/alacritty_terminal/0.25.1/source/src/grid/mod.rs), [selection API](https://docs.rs/alacritty_terminal/0.25.1/alacritty_terminal/selection/struct.Selection.html).

Implement `EventListener::send_event`: forward `PtyWrite` back into PTY input; answer `ColorRequest` and `TextAreaSizeRequest` with their formatter callbacks; preserve the formatter on `ClipboardLoad`; dispatch `ClipboardStore`, title, bell and wakeup to GPUI. These are explicitly responsibilities of the host UI, not automatic actions performed by Alacritty. Source: [Event API](https://docs.rs/alacritty_terminal/0.25.1/alacritty_terminal/event/enum.Event.html).

## PTY, input and ownership

Use `native_pty_system().openpty(PtySize)`; `CommandBuilder` selects the user's shell, project cwd, login/interactive arguments and environment (`TERM=xterm-256color`, `COLORTERM=truecolor`). `pair.slave.spawn_command(command)` launches a real shell. Drop the parent's slave immediately after spawning. Keep the master for resize, clone its reader, and take its writer once. `master.resize(PtySize)` updates the kernel and signals the foreground application. Sources: [portable-pty example](https://docs.rs/portable-pty/0.9.0/portable_pty/), [MasterPty API](https://docs.rs/portable-pty/0.9.0/portable_pty/trait.MasterPty.html).

Keep session ownership independent of sidebar visibility. Suggested design: blocking PTY reader/parser and input writer workers, a short-held terminal-state mutex, and coalesced asynchronous GPUI wakeups. Bound queued work to avoid memory growth during large output. Render a viewport snapshot rather than synchronously parsing arbitrary output on the UI thread. These are application design choices.

Take `child.clone_killer()` before moving `child` into a background `wait()` worker. On actual session disposal, signal/kill the child, close PTY handles, and reap it off the UI thread; do not join blocking workers inside render or UI drop. Collapsing the sidebar should keep the shell and history alive. Sources: [Child API](https://docs.rs/portable-pty/0.9.0/portable_pty/trait.Child.html), [ChildKiller API](https://docs.rs/portable-pty/0.9.0/portable_pty/trait.ChildKiller.html).

Implement GPUI `EntityInputHandler`; install `ElementInputHandler::new(bounds, entity)` using `Window::handle_input` during paint. Commit Unicode text through `replace_text_in_range`; retain preedit text through `replace_and_mark_text_in_range` and provide cursor bounds/UTF-16 ranges. Handle control and special keys through keydown without duplicating ordinary text. GPUI exposes all these callbacks in 0.2.2. Sources: [EntityInputHandler](https://docs.rs/gpui/0.2.2/gpui/trait.EntityInputHandler.html), [ElementInputHandler](https://docs.rs/gpui/0.2.2/gpui/struct.ElementInputHandler.html).

Application logic must also implement mode-aware application cursor keys, bracketed paste, focus reports, SGR mouse reports, and alternate-screen wheel behavior. Treat terminal focus as its own key context so viewer shortcuts do not intercept shell typing. These are acceptance requirements, not features provided by portable-pty.

If copying upstream renderer code, choose one offered license and retain its copyright/license notices. Original implementation against the public APIs avoids copying that component. Apache-2.0's distribution requirements are in the [upstream license](https://github.com/alacritty/alacritty/blob/master/LICENSE-APACHE); `gpui-terminal` also offers the [MIT license](https://github.com/zortax/gpui-terminal/blob/main/LICENSE-MIT).

## Implemented integration and selection readers

The application now owns the PTY model and GPUI renderer in `src/terminal.rs` and `src/terminal_view.rs`; it does not depend on `gpui-terminal`. Sessions are kept per canonical repository root. PTY parsing, writes, resize and image persistence run outside the UI thread. UI events use a bounded channel and visible views poll coalesced revisions.

The published GPUI 0.2.2 macOS backend has input/IME callbacks but no accessibility text elements for our custom views. A native probe initially returned `AXWindow` and `AXSelectedText` error `-25205` for a selected preview. The app-specific AppKit bridge now supplies read-only `AXTextArea` elements, selected text and UTF-16 ranges, and native Services copying for the preview and terminal. It leaves the reader's hotkey to macOS. API contracts: Apple's [accessibilitySelectedText](https://developer.apple.com/documentation/appkit/nsaccessibilityprotocol/accessibilityselectedtext()), [selectedText attribute](https://developer.apple.com/documentation/appkit/nsaccessibility-swift.struct/attribute/selectedtext), and the host SDK `NSAccessibilityProtocols.h`.

`swift scripts/check-selected-text.swift <pid> <expected>` checks the OS boundary. `scripts/check-desktop.swift` starts a disposable app process, selects both views, checks AX text and Cmd+C, saves and pastes a PNG path, verifies its exact bytes. The real-PTY unit test checks that separate sessions start in their project roots and preserve independent shell input. This verifies the system interfaces used by selection readers; it does not automate a particular third-party speech application's playback.
